## End-to-end repair and validation plan

The audit found a blocking issue: the homepage currently presents many not-yet-created calculator URLs as **Live**, so users can hit broken routes. I will repair truthfulness and existing functionality before exposing any additional tools.

### 1. Restore a truthful live catalogue and homepage
**Files:** `assets/js/tools.js`, `index.html`, `assets/js/layout.js`, `assets/js/calc-page.js`

- Restrict the public catalogue to calculator pages that actually exist and pass validation (currently 23 pages, including the newly added compound-interest page only after its selector bug is fixed and it passes checks).
- Remove every unpublished route from live cards, search, related tools, popular tools, calculated counts, sitemap, and service-worker cache.
- Retain the clearer category structure, but show only categories with genuinely live tools and calculate their counts from verified entries.
- Keep the **See more** behavior implemented, but only reveal extra verified live tools when the live catalogue exceeds 50. It will remain hidden until then.
- Remove inaccurate “50+ live/working” claims until all 50 routes have been implemented and verified.
- Keep category deep links working; update category-card clicks so their URL state remains shareable rather than being overwritten by `#tools`.

### 2. Repair correctness defects in existing calculators
**Files:** affected pages under `calculators/`, plus shared formatting/validation in `assets/js/core.js`

Priority formula and safety fixes:

- **Compound Interest:** wire the frequency segmented control to the existing `DC.initSegmented()` event contract so yearly/half-yearly/quarterly/monthly results truly differ.
- **Retirement:** prevent zero-return divide-by-zero; add validated bounds for retirement age, post-retirement years and income/investment fields.
- **Rent vs Buy:** replace the mismatched wealth calculation with a comparable monthly cash-flow model; include clear baseline assumptions and handle rent greater than EMI/loan tenure ending consistently.
- **Loan vs Investment:** compare equivalent terminal values/cash flows rather than investment value against interest-only savings.
- **Income Tax:** implement FY25–26 new-regime marginal relief around the ₹12L rebate threshold, or remove claims not actually calculated; reconcile surcharge wording with supported calculations.
- **Gratuity:** make ordinary-exit payouts zero below the stated 5-year eligibility threshold; keep any exception separate and explicit.
- **GST:** reject negative/custom rates that can divide by zero.
- **Health Insurance:** handle zero annual income without `Infinity%` output.
- **BMI:** require valid positive height/weight and avoid fabricated BMI 0 results; correct healthy range labels.
- **Pregnancy:** remove the automatic real-looking LMP demo result until a user provides input.
- **PPF / FD vs MF:** correct tax-saved and holding-period assumptions or make those assumptions explicit in the UI.

For every touched calculator, add semantic min/max/step constraints and explicit invalid-state messaging rather than silently turning blanks/non-finite values into ₹0.

### 3. Repair shared UI, accessibility, and no-JS resilience
**Files:** `assets/css/main.css`, `assets/js/core.js`, `assets/js/layout.js`, `index.html`, policy pages

- Remove the invalid extra CSS brace and consolidate conflicting mobile navigation spacing.
- Make the mobile drawer begin below the actual header height and provide focus management: focus enters menu on open, returns to toggle on close, Escape works, and background controls cannot be reached while visually blocked.
- Add consistent `:focus-visible` states for buttons, links, chips, cards, and controls.
- Upgrade FAQs with proper `aria-expanded`, `aria-controls`, and associated content panels.
- Add an accessible label to tool search and mark decorative search artwork hidden.
- Ensure reveal animation content remains visible when JavaScript is disabled; only animate after a JS-enabled class is present.
- Add sticky-header scroll offsets for `#categories`, `#tools`, and `#how`.
- Fix the hero text highlight stacking context and make header/footer ad wrappers actually use the shared container/gutter.
- Replace string-built toast message insertion with safe text-node insertion.
- Ensure policy pages load the ad initializer or, preferably, omit blank ad bands where ads are not intended; add consistent PWA metadata.

### 4. Repair production links and metadata
**Files:** `index.html`, `assets/js/layout.js`, new/static policy files, `sitemap.xml`, `sw.js`, `manifest.json`, `assets/img/`

- Keep the new About, Privacy, Terms, and Contact pages and validate their footer routes.
- Create the currently missing branded Open Graph image and validate its `og:image` reference.
- Update live-count text, schema description, footer copy, sitemap entries, PWA shortcuts, and service-worker precache entries from the verified catalogue—not manually maintained claims.
- Bump the service-worker cache version so users receive repaired CSS/JS/HTML rather than cached stale assets.

### 5. Run repeatable validation before claiming tools work
**New lightweight validation scripts/fixtures plus browser checks.**

- Static assertions: each registry entry has an existing page; each live page maps to the registry; no homepage/related/popular/footer link points to a missing local target; sitemap and SW routes match verified live pages.
- JavaScript/HTML checks for syntax errors, duplicate IDs, missing referenced elements/assets, and malformed markup.
- Known-answer calculation fixtures plus boundary tests: zero rate, zero income, blank/negative input, min/max values, rate thresholds, dates, and loan/tax/gratuity edge cases.
- Browser flows for every live tool: initial calculation, one changed input, slider/manual synchronization, segmented controls, charts, dark mode, FAQs, share/copy/print reachability, and no console errors.
- Responsive verification at 1440px desktop, 768px tablet, 390px and 360px mobile; check header/drawer, long outputs, charts/tables, focus states and horizontal overflow.
- Cross-browser matrix where available: Chromium, Firefox, WebKit/Safari-compatible rendering, plus offline/PWA cache upgrade tests.

### Outcome
After this phase, every tool shown publicly will have a real working route, validated calculations, accessible responsive UI, and consistent metadata. New tools will be added back to the catalogue only individually or in small batches after their pages and formula fixtures pass the same checks.
